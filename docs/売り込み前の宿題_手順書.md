# 売り込み前の宿題 手順書

営業を始める前に、神田さんが自分の手でやる3つの宿題です。上から順にやってください。
わからなくなったら、その画面のスクリーンショットをClaudeに貼れば続きを案内します。

**所要の目安**：①本番決済 半日（Stripeの審査待ちを除く） ／ ②山での実機テスト 1日 ／ ③法務表記の確認 2〜3時間

---

## ① 本番決済への切り替え

いまは「テストモード」（本物のお金が動かない）です。お客さんが払えるように、本番に切り替えます。
**テストモードのデータ（商品・リンク・顧客）は本番に引き継がれません。本番で作り直します。**

### 1-1. Stripeの本番を有効にする
1. https://dashboard.stripe.com にログインする
2. 画面左上のアカウント名の近くに「テスト環境」と出ていれば、まだテスト中。「本番環境を有効化」（Activate account）を押す
3. 聞かれたことを入力する：事業の種類（個人事業主か法人か）、代表者の情報、事業の内容、**売上の振込先の銀行口座**、本人確認書類
4. 終わると「本番環境」に切り替えられる。審査で数日かかることがある

### 1-2. 本番で商品を作る
1. 左上が **本番環境** になっていることを確認する（ここを間違えやすい）
2. 左メニュー「商品カタログ」→「商品を追加」
3. 名前：`TERRA 検収 年額プラン`
4. 価格：**9,800** ／ 通貨：**JPY** ／ 「定期支払い」→ 期間「年次」
5. 税：税込価格にする（アプリ・特商法の表示が「税込」のため）。インボイス登録事業者なら、税の設定とインボイス番号の登録も済ませる
6. 保存する

### 1-3. 無料お試しをStripe側でつけるか決める
- アプリの中には14日間の試用がもともとある（端末の中だけで数える。サーバーにデータは作られない）
- Stripe側にもお試しをつけるなら、商品の価格の設定で「トライアル期間」を入れる。**つけるなら、お試し中に解約した人は事務所のデータが見られなくなる**（今回実装したルールのとおり）
- つけないなら、何もしなくてよい

### 1-4. 決済リンク（Payment Link）を作る
1. 左メニュー「決済リンク」→「新規」
2. 1-2の商品を選ぶ
3. 「確認ページ」→「カスタムのURLにリダイレクト」を選び、次のURLを入れる
   `https://terra-kennsyuu-app.vercel.app/?checkout=success&session_id={CHECKOUT_SESSION_ID}`
   （`{CHECKOUT_SESSION_ID}` はそのまま。書き換えない）
4. 作成して、できた `https://buy.stripe.com/…` のURLをコピーする

### 1-5. お客さんが解約・支払い方法変更をする画面（カスタマーポータル）
1. 設定 →「請求」→「カスタマーポータル」を開く（**本番環境で**）
2. 「サブスクリプションのキャンセル」をオンにする。キャンセルは「期間の終了時」にしておくのがおすすめ
3. 「支払い方法の更新」をオンにする
4. 保存する

### 1-6. Vercelに本番の鍵を登録する
1. Stripe：開発者 → APIキー →「シークレットキー」（`sk_live_…`）をコピー
2. https://vercel.com でこのプロジェクト →「Settings」→「Environment Variables」
3. 次を登録（値は**このチャットやGitに貼らない**）

| 名前 | 値 |
| --- | --- |
| `STRIPE_SECRET_KEY` | `sk_live_…`（テストの `sk_test_…` から差し替え） |
| `LICENSE_SECRET` | 24文字以上のランダムな文字列。**一度決めたら二度と変えない**（変えると全員のコードが無効になる） |
| `OPERATOR_KEY` | 24文字以上のランダムな文字列（運営者コンソール用） |
| `PLATFORM_SERVICE_KEY` | 日報から事業体IDを先に発行するときだけ。24文字以上 |

4. 「Storage」→ Upstash Redis（Marketplace）を追加してプロジェクトにつなぐ。`KV_REST_API_URL` などは自動で入る
5. 「Deployments」→ 最新を「Redeploy」で再デプロイする

### 1-7. アプリのリンクを差し替える（これはClaudeがやる）
1-4でコピーした `https://buy.stripe.com/…` をClaudeに渡す。`src/js/config.js` の `stripe.checkoutUrl` を差し替えて公開する。

### 1-8. 本物のカードで通しテスト
1. 自分のカードで、本番の決済リンクから実際に購入する（9,800円が引き落とされる）
2. アプリに戻り、ライセンスコードが出て、使えることを確認する
3. 事務所の画面（`/office/`）で初期設定ができ、便を受け取れることを確認する
4. アプリのメニュー →「サブスクの管理」からポータルを開き、解約できることを確認する
5. 解約後、事務所の画面でデータが見られなくなる（「契約が終わっています」）ことを確認する
6. Stripeの「支払い」画面で、そのテスト購入を**返金**する

**ここまで通れば本番決済は完了です。**

## ② 実際の山での端末テスト

### 準備
- 端末：Android（Chrome）を優先。iPhone（Safari）があれば両方
- ホーム画面に追加して、アプリとして起動する
- 作業用の手袋、日が出ている屋外、トラックの荷台（検収する本物の積荷）

### チェックリスト（できたら ✓）
**起動と圏外**
- [ ] ホーム画面のアイコンから起動できる
- [ ] 機内モードにしてから起動しても、計測画面が開く
- [ ] 圏外で計測 → 出力 → 伝票履歴に残る（☁️＝同期待ち）
- [ ] 電波が戻ると、自動で✅になる

**手袋・日差し・揺れ**
- [ ] 手袋のままで、径級ボタンを押し間違えない
- [ ] 炎天下で数字・色が読める（配色は暫定。読みにくい色をメモ）
- [ ] 揺れる車内で「直前取消」を誤って押さない
- [ ] 画面が勝手に消えない
- [ ] 径級が1画面に収まる（7〜60cmの全域のとき）
- [ ] 左右のボタン配置を切り替えて、片手で押せる位置か

**本物の積荷で**
- [ ] 1台分を測り終え、合計本数・合計材積が手計算または工場の値と近い
- [ ] 複数の材を積んだとき（メニューの「複数の材を積む」をオン）、ロットの切り替えが迷わない
- [ ] 出力 → LINEで共有できる、CSVをExcelで開くと文字化けしない
- [ ] 音声入力は電波があるときだけ動く。圏外ではボタンが無効になり、案内が出る

**事務所との連携**（メニューの「事務所とデータを共有する」をオン）
- [ ] 出力した便が事務所の画面に届く
- [ ] 事務所で納入枠・お知らせを入れると、現場の画面に出る
- [ ] 事務所で工場の検収値を入れると「工場との差」に出る

### 問題の報告のしかた
気づいたことは、その場でスクリーンショットを撮り、次の形でClaudeに送る：
1. どの画面か（スクリーンショット）
2. 何をしたら
3. どうなったか（期待とどう違うか）
4. 端末と、そのときの状況（機種、明るさ、手袋の有無、圏外か）

## ③ 法務表記の確認

対象は `legal/` の4ページ：特定商取引法に基づく表記・利用規約・プライバシーポリシー・返金ポリシー。
**最後に、専門家（行政書士・弁護士）に一度見てもらうことを推奨します。**

### 自分で確認する項目
- [ ] **価格**：特商法の価格（年額9,800円・税込）が、アプリ内表示（`config.js` の `priceLabel`）とStripeの本番の商品価格と**3つとも一致**している
- [ ] **問い合わせ先**：`support@terra-tx-jp.com` に実際にメールが届く。別のメールアドレスから送って、神田さんのGmailに転送されるか試す（Cloudflareのメール転送の設定を確認）
- [ ] **所在地・電話番号**：いまは「請求があった場合、遅滞なく開示」としている。この書き方が使えるのは条件があるため、**専門家に確認**する（個人事業の自宅住所を出したくない場合に使われる書き方）
- [ ] **契約期間と解約**：「1年・自動更新」「解約は期間の終了時」が、Stripeのポータル設定（1-5）と食い違っていない
- [ ] **返金ポリシー**：実際にやる対応と書き方が合っている（購入直後の取り消しを認めるか、など）
- [ ] **データの同意**：利用規約 第5条・プライバシーポリシー 2-2（運営者のデータ閲覧と匿名化）の文面が、実際の仕組みと合っている。文面を変えたら `CONSENT_VERSION` の更新も必要（Claudeに依頼）
- [ ] **インボイス（適格請求書）**：登録事業者なら登録番号を特商法表記または請求書に載せる。未登録なら、その旨を問い合わせに答えられるようにしておく

### 追加で決めたいこと（今回の機能に関係）
- **契約が終わったあと、サーバーに残したデータを何日で消すか**（例：90日）。決めたら、規約とプライバシーポリシーに「契約終了後はデータの閲覧・書き出しができません。○日後に削除します」と書く。文面は専門家の確認が望ましい
- 契約終了後も運営者（神田さん）がデータを見てよいか。見ないなら、運営者コンソールでも終了済みの会社を見えなくする改修ができる

### 文面を直したいとき
直したい文面をClaudeに伝えれば、`legal/` を書き換えて公開できます。
