# 【TERRA共通方針】国内向けアプリの決済はStripeに統一します

> **正本は `kfrsj149-ai/terra-common`（rules/決済はStripeに統一.md）。** このファイルはコピー。内容が食い違うときは terra-common を正とする（2026-10-02〜）。

> 2026-09-28 決定 / 実証元：丸太検収PWA（terra-kennsyuu-app）
> 他のTERRA系プロジェクトのCLAUDE.md・コード・法務ページに反映してください。

---

## 1. 結論

**国内向けアプリの決済プラットフォームは Stripe に統一します。**
Lemon Squeezy は採用しません（海外向けを別途検討する場合のみ再考）。

すでに Lemon Squeezy で実装している場合は Stripe に差し替えてください。
以前「Lemon Squeezy は Merchant of Record なので個人事業主に有利」と記録していた
判断は、**国内向けについては誤り**でしたので取り消します。

---

## 2. なぜ Lemon Squeezy をやめたか

| 論点 | Lemon Squeezy | Stripe |
| --- | --- | --- |
| 請求通貨 | **表示を円にしても請求はUSD建て** | 円建てで完結 |
| 利用者の負担 | カード会社の海外事務手数料（1.6〜2.2%程度）が上乗せ | なし |
| 適格請求書（インボイス） | **発行できない** | ストライプジャパンは適格請求書発行事業者 |
| 手数料 | 5% + 50¢ | 3.6%（決済）+ 0.7%（Billing） |
| 消費税の申告・納付 | 代行してくれる | **自社で行う必要がある** |

決め手は上2つです。地方の林業事業者・個人事業主に対して、
カード明細に外貨取引として載る決済は、それだけで売れません。
法人相手だと適格請求書が出せないと仕入税額控除ができず、経費で落としにくい。

消費税の申告を自分でやる手間は増えますが、**国内向け・少額サブスクなら
「売りやすさ」を優先します。**

参考（年額9,800円税込の場合）：手数料は約421円、手取りは約9,379円。

---

## 3. 技術的な代償 ← ここが一番重要

**Stripeには「ブラウザから直接叩ける検証API」がありません。**
Lemon Squeezy にはライセンスキー検証APIがあり、アプリ単体で完結していました。
Stripe はシークレットキーが必須で、それをブラウザに置くと
第三者に決済を操作されます。絶対に置かないでください。

### → サーバーレス関数が必要です

「フロントエンドのみのPWA」という原則に、**決済確認だけ例外**を設けます。
ただし影響範囲は決済確認に閉じ込めてください。

- 業務機能（計測・計算・保存・出力）→ 従来どおり端末内で完結、圏外で動く
- サブスク確認 → オンライン時のみ・圏外猶予期間で吸収
- **npm依存パッケージは増やさない**（Node標準の `fetch` と `node:crypto` だけで書けます。
  `stripe` パッケージは入れない）

## 4. 実装の型（そのまま流用してください）

> **注（2026-10-01）**：ここに書いたライセンスコード方式は、**DBを持たないアプリ用**。
> Firestoreなどのサーバー側DBがあるアプリは、**WebhookでDBにサブスク状態を保存する方式**のほうが素直。
> 免税軽油PWAはその方式で実装済み（報告より）。DBがあるアプリは、そちらに合わせること。

```
api/_lib.js       Stripe呼び出し + ライセンスコードのHMAC署名（共通処理）
api/activate.js   有効化（決済完了の戻り / コード / 購入時メール）
api/verify.js     有効期限の再確認
api/portal.js     カスタマーポータル（解約・支払方法変更）のURL発行
```

### ライセンスコードの設計

- 中身は `{s: サブスクID, c: 顧客ID}` **だけ**
- これに `LICENSE_SECRET` で HMAC-SHA256 の署名を付ける（`base64url(本文).base64url(署名)`）
- **有効期限はコードに埋め込まない。** 毎回Stripeに問い合わせて取得する
  → 利用者がコードを書き換えて期限を延ばすことは原理的にできない
- 署名の比較は `timingSafeEqual` を使う

### 有効化の3経路（現場のおじさんが迷わない形）

1. **決済完了 → 自動有効化**
   Payment Link の遷移先を
   `https://<アプリのURL>/?checkout=success&session_id={CHECKOUT_SESSION_ID}`
   にしておく。アプリ起動時に `session_id` を拾って有効化し、
   `history.replaceState` でURLから消す（履歴に残さない）
2. **ライセンスコード** … 別端末に移すとき。メニューに表示してコピーできるようにする
3. **購入時のメールアドレス** … コード紛失・機種変更の復旧手段。
   Stripeの顧客をメールで検索して有効なサブスクを探す。
   止めたい場合のために環境変数 `ALLOW_EMAIL_ACTIVATION=false` で切れるようにしておく

### オフライン設計との整合

- 判定は「最後にオンライン確認できた日時 + 猶予日数」で行う（猶予30日で運用中）
- 初回起動から試用期間（14日）は無条件で使える
- **Service Worker は `/api/` をキャッシュしない。**
  古い「有効」の返事を返すと、解約後も使えてしまう
- サーバー障害（`server_error`）のときは判定を書き換えない。
  ここで無効にすると、Stripe側の一時障害で現場が止まる

## 5. ハマりどころ（実際に踏んだもの）

1. **`current_period_end` の置き場所がAPIバージョンで変わる**
   新しいバージョンではサブスクリプション本体から明細（`items.data[0]`）側へ移動しています。
   **両方を見るコードにしてください。** サンドボックスの実データで確認済み。

2. **JPYはゼロ十進通貨**
   `unit_amount: 9800` が9,800円です（98000ではない）。

3. **`tax_behavior: 'inclusive'`**
   「税込」で売るなら明示的に指定する。特商法表記の記載と必ず一致させる。

4. **`vercel.json` の `buildCommand` / `outputDirectory` を外す**
   これらが入っていると `/api/` がサーバーレス関数として認識されません。
   ビルド不要の素のPWAなら、これらの指定自体を削除するのが正解です。

5. **`cleanUrls: true` は引き続き禁止**（既知の圏外バグ。以前の共有どおり）

6. **カスタマーポータルは本番モードで一度ダッシュボードで保存が必要**
   （テストモードは自動で用意される）。これを忘れると解約導線が死にます。

## 6. 公開前に必要な設定

### Vercelの環境変数

| 名前 | 値 |
| --- | --- |
| `STRIPE_SECRET_KEY` | Stripeのシークレットキー（`sk_test_...` / 本番は `sk_live_...`）。**絶対にGitにコミットしない** |
| `LICENSE_SECRET` | `openssl rand -base64 32` の出力。**一度決めたら変更しない**（既存コードが全部無効になる） |
| `ALLOW_EMAIL_ACTIVATION` | 任意。`false` でメール復旧を停止 |

### Stripe側

1. 商品と価格（JPY・年額・税込）
2. 決済リンク（Payment Link）。遷移先に `{CHECKOUT_SESSION_ID}` を入れる
3. カスタマーポータルを保存（設定 → 請求 → カスタマーポータル）

**サンドボックスと本番は完全に別物です。** 本番化のときは商品・価格・決済リンクを
作り直し、アプリの設定ファイルのURLを差し替えてください。

## 7. 法務ページに反映する文言

特商法表記・返金方針・プライバシーポリシーの記載を、以下に差し替えてください。

- 支払方法 → `決済代行事業者：ストライプジャパン株式会社（Stripe）`
- 契約期間・自動更新 → `契約期間は1年間とし、期間満了日に同一条件で自動更新されます。`
  `更新を希望されない場合は、期間満了日までに、アプリのメニュー内「支払い・プラン管理」から`
  `開く管理画面（Stripeカスタマーポータル）で解約手続きを行ってください。`
  `解約後も期間満了日まではご利用いただけます。`
- サービスの提供時期 → `決済完了後、ただちにご利用いただけます。決済が完了すると自動的に`
  `アプリへ戻り、その端末で利用できる状態になります。`
- 返金 → `決済代行事業者（ストライプジャパン株式会社）を通じて、原則としてお支払いに`
  `用いられた方法で返金します。`
- プライバシーポリシー → 「決済事業者へライセンスキーを送信」ではなく、
  `本アプリのサーバーへライセンスコードを送信し、サーバーが決済事業者へ照会します。`
  `業務データは一切送信しません。` と書く（実態が変わったため）
- 制定日 → **空文言にしない。** 具体的な日付を入れる

事業者情報は Logging Scorer と同一で固定：
TERRA TX（運営責任者：神田 愼太郎）/ support@terra-tx-jp.com /
所在地・電話番号は請求があった場合に遅滞なく開示 / 日本法・盛岡地方裁判所

## 8. テストの書き方

Stripeへの通信は `globalThis.fetch` を差し替えて検証します（実際に課金しない）。
最低限、次の2つは必ずテストしてください。

1. **ライセンスコードを改ざんすると通らないこと**
   （本文だけ他人のサブスクIDに書き換えたコードが `null` になる）
2. **Stripeの返事から有効期限を正しく取り出せること**
   （本体側・明細側の両方のパターン）

あわせて、解約済み（`canceled`）は無効・支払リトライ中（`past_due`）は
**現場を止めない**、という方針も固定しておいてください。
