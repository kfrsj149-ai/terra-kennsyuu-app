# 依頼：日報PWA（NIPPO-RA）の引き継ぎ文書を作る

> 日報PWAのClaudeに貼る依頼文。2026-10-01、神田さんの意向。
> 日報PWAのコードは捨てて免税軽油PWAに吸収する。**ただし設計思想・判断・修正の履歴は捨てない**。

## 依頼文（そのまま貼る）

```
【お願い】日報PWA（NIPPO-RA）の「引き継ぎ文書」を作ってください

背景：日報PWAのコードは捨てて、免税軽油PWAに吸収合併します。
ただし、これまでの設計思想・判断・神田さんの指摘は捨てたくありません。
免税軽油PWAのClaudeが同じ指摘を繰り返さず、早く正しく作れるように、
引き継ぎ文書を1つ作ってください。

■ 書くこと（コードの貼り付けは不要。理由を書く）
1. このアプリは何のために作ったか（目的・原点・誰が使うか）
2. 設計の考え方と、その理由（なぜその項目か、なぜその画面か）
3. 神田さんに修正・却下された点の履歴  ← 最重要
   「最初はこう作った → 神田さんに『違う』と言われた → こう直した → 理由」
   却下された案は、却下された理由も必ず書く
4. 現場で決まったルール（用語、文言、UIの原則、手袋・屋外・1秒完了など）
5. 日報の各項目の意味と、なぜ必要か
   （現場・天候・路面・風速・参加作業員・稼働時間帯 ほか）
6. 権限・閲覧の考え方（現状はフラット。なぜそうしたか。足りない点）
7. 未解決・保留にしていること
8. 免税軽油PWAに「持っていくもの」と「捨てるもの」の仕分け

■ 守ること
- コミット履歴、docs、構想メモ、コードのコメントなど、
  リポジトリで確認できる根拠から書く
- 確認できないことは「未確認」と書く。推測で埋めない
- 鍵・パスワード・個人情報は書かない
- 保存場所：docs/ の下に1ファイル（例：docs/handoff-to-menzei.md）
- 書いたら、神田さんに「ここに足りない記憶はありますか」と聞く
```

## 補足（神田さんへ）

- 日報PWAのClaudeが知っているのは、**リポジトリに残っていることと、そのセッションの履歴だけ**。
  過去のチャットが消えていれば、神田さんの指摘は、コミットメッセージやdocsに残っているものしか書けない
- だから、書かれた引き継ぎ文書に、**神田さんの記憶を口述で足す**のが一番効く
  （「そこは違う」と言ったことを、思い出せる分だけ）
- 引き継ぎ文書ができたら、免税軽油PWAのClaudeに「最初にこれを読んでから作業して」と渡す
