# 事務所端末のセットアップ手順

> 2026-10-01 実装。事務所用の画面（`/office/`）と、現場アプリとのデータ連携の準備手順です。
> **コードは公開済みですが、「保存先」を足すまでは動きません**（動かないだけで、現場アプリの計測・保存には影響しません）。

## 全体の流れ（約10分）

1. Vercel に「保存先」（Upstash Redis）を足す　← **ここだけ神田さんの操作が必要**
2. 事務所のPCで `/office/` を開き、事務所の初期設定をする
3. 現場アプリで「事務所とデータを共有する」をオンにする

---

## 1. Vercel に保存先を足す

事務所に届く便・納入枠・お知らせ・現場の台帳は、**Upstash Redis**（無料枠あり）に保存します。
Vercelの画面からボタンで足せます。（画面の文言は、Vercel側の更新で少し違うことがあります）

1. https://vercel.com にログインし、プロジェクト `terra-kennsyuu-app` を開く
2. 上のメニューの **「Storage」** を開く
3. **Upstash**（「Redis」と書かれたもの）を選び、「Create」または「Connect」を押す
   - 地域（Region）は **日本（Tokyo / ap-northeast-1）** が近くて速い
   - 料金は **無料プラン（Free）** でよい
4. 「このプロジェクトにつなぐ（Connect Project）」で `terra-kennsyuu-app` を選ぶ
   - 環境変数（`KV_REST_API_URL` と `KV_REST_API_TOKEN`）が**自動で**入ります。自分で入力する必要はありません
5. **再デプロイ（Redeploy）する**：「Deployments」→ 一番上の ⋯ →「Redeploy」
   （環境変数は、再デプロイしないと反映されません）

### うまくいったか確かめる

`https://terra-kennsyuu-app.vercel.app/office/` を開いてください。ログイン画面が出ればOKです。
（保存先がまだのときは、初期設定で「データの保存先がまだ設定されていません」と出ます）

> 環境変数 `LICENSE_SECRET` と `STRIPE_SECRET_KEY` は、決済のために別途必要です（`README.md` 参照）。
> 事務所端末も、同じ `LICENSE_SECRET` で動きます。**`LICENSE_SECRET` は一度決めたら変えないでください**
> （変えると、発行済みのライセンスコードと事務所のログインがすべて無効になります）。

---

## 2. 事務所の初期設定（事務所のPCで）

1. 現場アプリのメニュー →「サブスクリプション」→ **ライセンスコードをコピー**
   （購入済みの端末でないと表示されません）
2. 事務所のPCで `/office/` を開く
3. 「はじめて使う（事務所の初期設定）」を開き、**ライセンスコード**と、**購入時にStripeへ登録したメールアドレス**を入れ、
   **「データの取り扱いに同意します」にチェック**して「事務所の画面をつくる」（同意しないと設定できません。同意の内容は下の「データの取り扱い」）
   （メールアドレスは、契約者ご本人かどうかの確認に使います。運転手さんなど、ライセンスコードだけを知っている人は設定できません）
4. **事務所コード（12文字）が1回だけ表示されます。** 紙に書くか、パスワード管理アプリに保存してください
   （「控えました」にチェックしないと閉じられません）

> ライセンスコードだけでは、事務所の初期設定も、事務所の画面へのログインもできません
> （初期設定には購入時のメールアドレス、ログインには事務所コードが要ります）。

以後のログインは「ライセンスコード＋事務所コード」。**同じPCなら、2回目以降はコードの入力は要りません**（30日間ログインが続きます）。

### 事務員さんのスマホでも使う

PCの「設定」→「ログイン用リンクをコピー」→ LINEなどで自分のスマホに送って開くと、スマホでもログインできます。
スマホでは **「受信箱」→「📷 写真を送る」** で、FAXや精算書を撮って送れます。PCの受信箱に届き、
納入枠やお知らせに添付できます。（アプリのインストールは要りません）

---

## 3. 現場アプリでオンにする

現場アプリのメニュー →「事務所とデータを共有する（試験中）」をオン。**初期はオフ**です。

- オンにした後に出力した便が、通信できるときに自動で事務所に届きます（圏外のときは端末に残り、電波が戻ると送られます）
- 事務所が出した納入枠・お知らせ・現場の台帳が、端末に届きます
  - お知らせ（納入不可・入場制限）は、**画面の一番上に赤／橙の帯**で出ます
  - 納入先を選ぶと、**枠の残りと、いま荷下ろしできるか**が出ます
  - 現場名と納入先の選択肢に、事務所が登録した名前が先頭に並びます
- 圏外では、**最後に受け取った内容**を表示します。「最終更新」を必ず添え、圏外のときは「最新でない可能性があります」と出します

## 事務所の画面でできること

| タブ | できること |
| --- | --- |
| 便 | 現場から届いた便の一覧・納入先ごとの合計・**工場の検収値の入力（現場の値との差が出る）**・Excel用CSV |
| 納入枠 | 組合・工場の「納入可能枠」を登録。**消化（確定＝工場の値／見込み＝現場の値）と残り**、曜日・時間帯、FAXの写真の添付 |
| お知らせ | 納入不可・入場制限・案内を出す。期限が来たら自動で消える。工場や土場を指定できる |
| 現場 | **現場の台帳**（ID・名前・別名・林班・住所）。現場の端末が自由入力した名前の**名寄せ** |
| 受信箱 | スマホで撮った写真を受け取る |
| 設定 | スマホ用ログインリンク・事務所コードの再発行・別アプリの契約をつなぐ |

## 運営者（神田さん）が全社のデータを見る：運営者コンソール `/ops/`

事務所に共有された検収データを、運営者が閲覧し、匿名化して書き出すための画面です。**URLは誰にもリンクしておらず、検索にも載りません。**

### 使えるようにする（1回だけ）

1. 長いランダムな文字列（**24文字以上**）を作る。パソコンなら `openssl rand -base64 32`、またはパスワード管理アプリの「パスワード生成」でよい
2. Vercel の「Settings」→「Environment Variables」に、名前 **`OPERATOR_KEY`**、値に上の文字列を登録する
3. **再デプロイ**する
4. `https://terra-kennsyuu-app.vercel.app/ops/` を開き、その文字列でログインする

> この鍵は、**全社のデータを見られる合鍵**です。他の人に教えない・チャットに貼らない・紙に残さない（パスワード管理アプリに保存）。
> **必ずランダムに生成した長い文字列にしてください**（人が考えた合言葉は推測されやすく、ロックの保護も当てになりません）。
> 漏れたと思ったら、Vercelで値を変えて再デプロイすると、古い鍵とログイン済みの札がすべて無効になります。
> 1つのIPから9回目の試行はロックされます（15分）。ログインの札は12時間で切れ、「ログアウト」を押すと、発行済みの札がすべてサーバー側でも無効になります。

### できること

| タブ | 内容 |
| --- | --- |
| 会社 | 事務所を設定した事業体の一覧（設定した日・便に入っている会社名・最新の便・同意の状態・便数）。「便を見る」で**生データ**（車番・納入先・現場・備考を含む）を閲覧。**同意が現行版でない会社は、存在と便数だけで、中身は見られません** |
| 匿名化エクスポート | **集計**（月×樹種×長さ×径級）または**個別**（書き出しごとに変わる仮名の会社つき1行ずつ）をCSVで書き出す。期間は**月単位・確定した過去の月だけ** |
| 閲覧記録 | ログイン（失敗・ロックも）・一覧・閲覧・書き出し・記録の閲覧の履歴（いつ・何を・どの会社を・どの期間）。IPそのものは残さず、指紋だけ |

### 守っていること

- **閲覧専用**です。会社のデータを書き換える操作はありません（自動テストで確認）
- **すべての閲覧・書き出しを記録**します（運営者自身の操作も）。取引先や利用者から「見ていないと言えるか」を問われたときの根拠になります
- 書き出しに使うのは、**現行の同意文に同意した会社のデータだけ**です
- 匿名化の書き出しには、**会社名・車番・現場名・納入先・備考・伝票番号・便ID・正確な日付を含めません**（月までに丸める）
- **少数の組み合わせは出しません**：関わった会社が3社未満、または**1社の寄与が8割を超える**組み合わせ（kは3未満にできません）
- **期間をずらした差分への対策**：期間は月単位で、確定した過去の月だけ。同じ条件で書き出し直すと、**凍結した同じ結果**を返します
  （日単位で期間をずらして2回書き出し、引き算すると、特定の1社・1日分が分かってしまうため）。「作り直す」と最新になりますが、閲覧記録に残ります。
  **第三者へ渡した書き出しがある月は、作り直さないでください**
- **架空の行への対策**：事務所に届く便は、本数0の行や、径級・本数と合わない材積をサーバーが拒否します（会社数の水増しを防ぐ）
- 会社は**書き出しごとに変わる鍵付きの仮名**にします。別々の書き出し同士は結合できません

**できないこと（正直に）**
- 仮名は、運営者が鍵（`LICENSE_SECRET`）と会社一覧を持っていれば、**再計算して元の会社に結びつけられます**。個別モードは「匿名」ではなく「仮名化」で、第三者に渡すときの保護です
- 同じ人が複数の契約を作って会社数を水増しすることは、見分けられません
- 閲覧記録は、保存先（Upstash）の認証情報を持つ人なら消せます（APIの上では消す操作がない、という意味です）
- `LICENSE_SECRET` を変えると、ライセンスコードと事務所のログインがすべて無効になります（仮名は書き出しごとに変わるので、仮名への影響はありません）

> ⚠ **「匿名化」は、個人情報保護法の「匿名加工情報」の基準を満たすことまでは保証しません。**
> データを第三者へ販売・提供する前に、必ず専門家（弁護士など）に確認してください。
> 特に、少数の会社しか扱わない樹種・地域・期間の組み合わせは、個別の事業体が推測される可能性があります。kを大きくする、期間を粗くする、などで調整してください。

## データの取り扱い（利用者の同意）

事務所の初期設定のとき、利用者は次の内容に同意します（文面：`legal/terms/`（第5条）・`legal/privacy/`（2-2））。

1. 事務所に共有された検収データ（生データ）を、運営者（TERRA TX）が閲覧できる
2. 研究・販売などに利用する場合は、会社名・車番・現場名などを除いて**匿名化したうえで**利用する

- 同意は、サーバーが「同意した文面の版と日時」を会社ごとに記録します。**同意なしでは、事務所の初期設定ができず、便も受け取りません。**
- 現場アプリでも、「事務所とデータを共有する」を初めてオンにするとき、同じ内容を見せて同意を取ります（同意しなければオンになりません）。
- **同意文を変えたとき**は、`src/js/office-rules.js` の `CONSENT_VERSION`（日付）を更新します。更新すると、事務所は次のログインで**改めて同意するまで、便の受信が止まります**
  （既存のデータは残り、読めます）。同意し直していない会社のデータは、匿名化の書き出しにも含まれません。
- 同意の撤回：共有をオフにする。送信済みのデータの削除は、請求を受けて運営者が行います。**すでに匿名化して利用・提供したデータは、取り出して削除できません**（ポリシーに明記済み）。

## 困ったとき

| 状況 | 対処 |
| --- | --- |
| 事務所コードをなくした | ログイン画面の「事務所コードをなくした」から、**ライセンスコード＋購入時のメールアドレス**で、新しい事務所コードを受け取れます（事務所のPCがログイン済みなら、「設定」→「事務所コードを作り直す」でも可）。古いコードと、ログイン済みのすべての端末は使えなくなります。**データは残ります** |
| 「15分間ログインできません」と出る | 事務所コードの間違いが続いたための安全装置です。15分待つか、上の「メールでの復旧」を使えば入れます |
| 担当者が替わった | 事務所コードを作り直す。古いコードと、ログイン済みのすべての端末が使えなくなります |
| 現場の端末に「事務所の初期設定がまだ」と出る | 手順2が済んでいません |
| 送信済みのデータを消したい | 事務所の画面で便ごとに削除できます。全部を消す場合は運営者に連絡してください |

## 仕組みと限界（運営者向け）

- 会社の見分け方：ライセンスコード（Stripeの顧客ID入り・署名付き）→ **事業体ID**（初期設定のときにサーバーが発行する8文字）。
  データは事業体IDごとに分けて保存し、他社のデータは構造上読めません（自動テストで確認済み）。
- 事務所コードは**ハッシュ（scrypt）だけ**をサーバーに残します。再発行すると、古い札はすべて無効になります。
- 事務所コードの総当たりは、8回間違えると15分ロックします。ライセンスコードを持つ人が故意に間違えて、事務所を締め出すことは可能ですが、
  契約者本人は「購入時のメールアドレス」で復旧できるため、締め出しは長続きしません。
- 初期設定と復旧は、**Stripeに登録された購入時のメールアドレス**との一致が条件です（8回間違えると15分ロック）。
  メールアドレスが登録されていない契約は、安全のため設定できません（`no_email`）。
- 上限：1社あたり **便15,000件**、**1分に120件**まで送信、**1便12KB**まで。共有の保存先を、1社が使い切らないための安全装置です（通常の使い方では届きません）。
  枠の集計で読む便が多すぎるときは、画面に警告が出ます。
- Stripeに繋がらないとき（通信エラー・5xx）は、最近有効と確認できていれば30日まで通します。
  契約が存在しない（404）・鍵や設定の誤り（401/403）のときは、猶予を与えません。
- 工場の検収値は、便とは別の場所に保存しています（現場からの再送と、事務所の入力が、お互いを上書きしないため）。
- 契約が有効かどうかは、Stripeに確認して1時間キャッシュします。Stripeに繋がらないときは、最近（30日以内）有効と確認できていれば通します。
- 事務所の画面（`/office/`）はオンライン専用で、Service Workerのキャッシュ対象外です。
- API は `/api/office` の1本だけです（Vercel無料プランの「関数12個まで」を使い切らないため）。
- **外注の運送会社への配信は未実装**です。現場アプリ（ライセンスコードを持つ端末）にだけ届きます。
- **QRコードの読み取りは、この画面ではやっていません。** 機械・車両のQRは免税軽油PWAに集約する決定です（`docs/QR書式の統一.md`）。
  事務員のスマホは、写真（FAX・精算書）を送る受信箱で、PCとつなぎます。
- 手元での動作確認：`OFFICE_DEV=1 LICENSE_SECRET=適当な長い文字列 STRIPE_SECRET_KEY=x npm run dev`
  （メモリに保存し、サブスクを常に有効にして動かします。再起動で消えます。本番では使いません）
